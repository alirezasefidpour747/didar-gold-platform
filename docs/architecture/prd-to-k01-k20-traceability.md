## Method and status legend

Requirements were extracted from the executive sections, S1–S33, M1–M29, F1–F23, roles, phases, revenue/KPI tables, governance/RACI, integrations, and cross-cutting controls. Repeated statements were merged when they expressed the same outcome; all source references were retained. Page references below are PDF page numbers (the printed footer is one less after the cover).

Each row has exactly one primary destination and one maturity status. Codes map to the required statuses:

| Code | Coverage status |
|---|---|
| `FULL` | Fully covered by current design |
| `PART` | Partially covered by current design |
| `OUT` | Designed outside K01–K20 |
| `DEMO` | Present only as demo/mock |
| `FE` | Present only in frontend |
| `MISS` | Missing |
| `CONFLICT` | Conflicting |
| `OWNER` | Requires owner decision |
| `DEFER` | Explicitly deferred |
| `OOS` | Explicitly out of scope |

Priority is inferred from PRD language and workflow dependency: `P0` blocks a safe core transaction, `P1` is required for a controlled product, and `P2` is commercial optimization.

## Proposed implementation roadmap

This roadmap is a proposal only. Each gate requires approved owner decisions, migration/rollback evidence, authorization tests, audit evidence and recovery testing.

2. **Core K01–K20 business foundation** — In dependency order: K02 onboarding; K05/K07 catalog/supplier; K06/K08/K09 item intake/custody; K10/K11/K12 order/retail operations; K13/K14/K15 financial policy/credit/ledger; K16 integration state; K17/K18 warranty/service; K19/K20 circular lifecycle. Each module migrates independently behind tested contracts.
3. **PaaS/EventMesh** — Durable outbox publisher, inbox consumers, schema registry/versioning, API gateway policy, search indexing, replay/dead-letter and operational observability. EventMesh must carry facts from sources of truth, never become another business master.
4. **MDM** — Durable product/material/category/reference dictionaries, stewardship workflow, effective versions and distribution to K05/K08/K13/search/BI.
5. **BI and risk analytics** — Reconciled fact/dimension model, metric catalog/lineage, row-level access, dashboards, then governed forecasting/anomaly/recommendation. Replace all seeded metrics; models remain advisory.
6. **External integrations** — Certify providers one adapter at a time: identity/KYB, RFID/lab/rate, ERP/tax, courier/insurance, bank/PSP/custodian, bureau/lender. Require sandbox contract tests and reconciliation before enabling financial/custody finality.
7. **Customer/seller/supplier portals** — Build role-specific Persian/accessibility-tested experiences only on secured, versioned APIs: seller ordering/warranty; consumer ownership/service/buyback; supplier catalog/agreement/capacity. Gallery is a presentation composition, not authoritative storage.
8. **Deferred commercial capabilities** — Campaigns, collaborative preorder, events, promotions, loyalty, consumer lending, advanced studio/content, data monetization and advanced trend AI proceed only after core controls and separate business/legal approval.

## Overall conclusion

**K01–K20 do not fully replace the legacy PRD.** They provide a substantially stronger proposed transactional backbone for identity, catalog, provenance, custody, ordering, pricing, credit, accounting, warranty, service and circular gold flows. The PRD also requires platform security, PaaS/search/events, MDM, BI/risk, real external providers, multi-role portals and deferred commercial capabilities. Thirteen requirements are missing from current design, ten are explicitly conflicting, and many “present” code paths are only UI/demo/in-memory behavior.

C01–C09 now have adopted architecture dispositions in the unified decision package. The ten Package 3A decisions are approved, with D44–D46 exact legal details conditional; remaining policies still require their applicable owners. The next implementation work begins with **Package 3A: identity/organization normalization and K01 hardening**, not a broad simultaneous authentication/RBAC/audit/event rollout.
